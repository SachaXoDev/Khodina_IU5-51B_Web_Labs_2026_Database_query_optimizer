# Каталог индексов — настольное приложение на Tauri 2

Дополнительное задание «Нативное приложение с ИИ». Гость может просматривать каталог, применять фильтры, перелистывать страницы и открывать карточки. Поиск по изображению работает прямо в каталоге. Вход, редактирование и отправка фотографий на сервер не предусмотрены.

В этой ветке также есть [сервер NestJS](../database_query_optimizer) с гостевым методом выдачи кандидатов для CLIP. Для каталога и поиска из приложения запустите сервер отдельно. Офлайн-калибровку можно выполнить без сервера.

## Запуск и сборка

Нужны Node.js 22.12+ (или 20.19+) и актуальная стабильная версия Rust (для HTTP-плагина — не ниже 1.90). Установите [зависимости Tauri для своей ОС](https://v2.tauri.app/start/prerequisites/): Xcode Command Line Tools на macOS, WebKitGTK 4.1 и библиотеки сборки на Linux либо MSVC Build Tools и WebView2 на Windows. Для CLIP нужны WebAssembly SIMD, модульные воркеры и поддержка `OffscreenCanvas`/`createImageBitmap` в воркерах. Для macOS рекомендуется версия 14 или новее. Отдельно устанавливать Cargo Tauri CLI не требуется.

```sh
# Из корня репозитория:
cd native-tauri
npm ci
cp .env.example .env.local
# В .env.local укажите адрес API и, при необходимости, отдельный адрес MinIO.
npm run tauri -- dev
npm run tauri -- build --bundles app    # macOS: .app; для образа диска — dmg
# Linux: --bundles deb или appimage. Windows: --bundles nsis.
```

Готовый пакет находится в `src-tauri/target/release/bundle/`. Адрес API задаётся при сборке и отображается в верхней части окна. При смене IP или порта приложение нужно пересобрать. Адреса можно передать и прямо в командной строке, подставив IP своего сервера:

```sh
VITE_API_URL=http://192.168.1.78:3108 VITE_MEDIA_URL=http://192.168.1.78:9018 npm run tauri -- build --bundles app
```

Чтобы CLIP работал без загрузки весов из интернета при первом запуске, подготовьте файлы модели q8 и включите `VITE_BUNDLE_CLIP=1`. Для получения карточек по-прежнему нужен работающий API в локальной сети.

```sh
node scripts/bundle-clip.mjs
VITE_BUNDLE_CLIP=1 VITE_API_URL=http://192.168.1.78:3108 VITE_MEDIA_URL=http://192.168.1.78:9018 npm run tauri -- build --bundles app
```

Скрипт использует уже скачанные веса или загружает их заново. Файлы в `public/models/` не отслеживаются Git. Для компактной сборки с загрузкой модели при первом поиске этот каталог не нужен.

Запустите сервер на интерфейсе, доступном из локальной сети, и разрешите доступ к портам API и MinIO. `VITE_API_URL` — HTTP-адрес с частным IPv4 по RFC 1918, **без `/api`**. Loopback, имена хостов, учётные данные в URL и публичные адреса не допускаются. По умолчанию `VITE_MEDIA_URL` использует IP API и порт 9000. Миниатюры должны приходить по `/media/…` или `/assets/…`: подходят относительные ссылки и абсолютные ссылки на настроенные адреса. Клиент не переписывает абсолютные и подписанные ссылки. Если миниатюра недоступна, отображается заглушка.

Команда `npm run tauri` передаёт Vite адреса сервисов и ограничивает разрешение Tauri гостевыми маршрутами API и миниатюр для окна `main`. Не заменяйте её на `npx tauri dev/build`: запросы выполняются через [HTTP-плагин Tauri](https://v2.tauri.app/plugin/http-client/), а не обычную вкладку браузера. Клиент не отправляет cookies и не следует перенаправлениям. Изображения отображаются через локальные URL объектов после проверки типа и размера. Loopback используется только для интерфейса Vite в режиме разработки, не для API. Политика CSP разрешает локальные ресурсы, воркеры, WASM и загрузку модели по HTTPS с Hugging Face. Используйте HTTP API только в доверенной локальной сети: трафик не шифруется.

## Локальный поиск CLIP и подбор порога

Гостевой метод `GET /api/indexes/clip-candidates?afterId=0&limit=100` возвращает `{items: [{id, shortDescription}], nextAfterId}`. Оба параметра необязательны: `afterId` — целое от 0 до 2147483647, `limit` — от 1 до 100. Карточки упорядочены по ID. Клиент передаёт `nextAfterId` в следующий запрос, пока сервер не вернёт `null`. Поиск обходит все страницы независимо от фильтров каталога. Кандидаты — опубликованные карточки с описаниями длиной 50–100 символов после обрезки пробелов, для которых CLD3 определяет английский как наиболее вероятный язык. Определение языка приблизительно. Записи `demo_bench_idx_######` исключаются; прежний флаг `clip_candidate` на отбор не влияет.

Воркер использует [Xenova/clip-vit-base-patch32](https://huggingface.co/Xenova/clip-vit-base-patch32/tree/6b7c523703ae26e39be4b03774966f8571c7f523) и Transformers.js 3.8.1. Текстовый и визуальный ONNX-энкодеры q8 занимают суммарно около 154 МБ; если они не встроены, веса загружаются при первом запуске поиска. Среда ONNX WASM входит в сборку. Вектор фото вычисляется один раз на поиск, а загруженная модель и ограниченный кеш текстовых векторов используются повторно. Поддерживаются JPEG, PNG и WebP до 10 МиБ и 16 мегапикселей. Изображение остаётся на устройстве.

CLIP переводит фото и описание в общее 512-мерное пространство. После L2-нормализации скалярное произведение даёт косинус `c ∈ [-1, 1]`. В интерфейсе видны и `c`, и `score = (c + 1) / 2`. `score` сохраняет порядок результатов и **не является вероятностью**. Сначала применяется порог по `score` (от 0,40 до 0,90 включительно), затем берутся не более `TopK` результатов из общего списка по убыванию сходства (от 1 до 20; при равенстве — по ID). Если никто не прошёл порог, выдача пуста. Диагностика показывает и оценки ниже порога. Порог и TopK можно менять без повторного запуска модели.

В приложении откройте **«Поиск по изображению» → «Выбрать файл»**, выберите JPEG, PNG или WebP и нажмите **«Найти совпадения»**. Для быстрой проверки кнопка **«Проверить на примере»** использует встроенный `index_users_email.jpg`.

Команды калибровки после установки зависимостей:

```sh
npm run calibrate
# С работающим API и 14 демонстрационными описаниями в PostgreSQL:
CLIP_DEMO_API=http://192.168.1.78:3108 npm run calibrate
```

Для прогона с API подготовьте отдельную учебную БД со схемой и демонстрационными пользователями, затем из корня репозитория выполните `psql "$DEMO_DATABASE_URL" -v demo_seed_confirm=1 -f scripts/demo_optimizer_seed.sql`. Фотографии из `fixtures/` — входные файлы для калибровки; для каталога сервер отдельно отдаёт миниатюры по `/media/`.

Без API скрипт читает 14 описаний из SQL-файла. С API он обходит все страницы, но отмечает только известные 14 описаний; прочие результаты остаются без разметки. Набор включает четыре изображения с подходящей карточкой и два без совпадения **среди этих 14 описаний**. Скрипт оценивает пороги с шагом 0,01 по F1 до ограничения TopK и сравнивает `TopK = 1, 3, 5` при штатном пороге. Офлайн-прогон использует ONNX Runtime CPU, а приложение — WASM и декодирование изображений в WebView; оценки могут немного различаться.

При совместном подборе по сохранённым оценкам **порог 0,63 и `TopK = 1`** дали четыре верных совпадения без ложных результатов. При том же пороге `TopK = 3` и `5` добавили по четыре ложных результата, не прибавив верных. В интерфейсе по умолчанию остаётся **0,65**: на этом наборе при `TopK = 1` получены три верных совпадения без ложных, одно пропущено. Порог **0,63** можно выставить вручную.

Этот подбор проведён на учебных примерах и не заменяет проверку на независимой выборке. Для такой проверки нужны новые изображения, размеченные подходящие карточки и примеры без совпадений.
