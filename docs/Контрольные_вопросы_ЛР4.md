# Шпаргалка по контрольным вопросам к защите Лабораторной работы №4

## 1. Куки (Cookies)
• Небольшой фрагмент данных (ключ-значение), который сервер отправляет браузеру в заголовке `Set-Cookie`.
• Браузер автоматически сохраняет куку и передает её в заголовке `Cookie` при каждом последующем запросе к этому домену.
• Флаги безопасности:
  - `HttpOnly`: запрещает чтение куки из JavaScript (`document.cookie`), защищает сессию от кражи при XSS-атаках.
  - `Secure`: передача куки только по защищенному протоколу HTTPS.
  - `SameSite` (`Strict` / `Lax` / `None`): защищает от межсайтовой подделки запросов (CSRF).

## 2. Сессия (Session)
• Stateful-механизм аутентификации.
• Сервер создает объект сессии и сохраняет его во внешнем хранилище (Redis или БД).
• Клиенту отдается только случайный идентификатор сессии `sessionId` (UUID).
• Плюсы: мгновенный отзыв доступа (logout) удалением ключа из хранилища; клиент не знает чувствительных данных.

## 3. Redis
• Высокопроизводительная in-memory (в оперативной памяти) база данных типа «ключ-значение».
• Зачем нужен для сессий:
  - Скорость: чтение и запись за доли миллисекунды (O(1)).
  - Встроенный TTL (Time To Live): автоматическое удаление сессии по истечении времени (например, 3600 сек).
  - Масштабируемость: единое централизованное хранилище сессий для нескольких инстансов бэкенда (в кластере).

## 4. JWT (JSON Web Token)
• Stateless-механизм аутентификации (токен состоит из 3 частей: Header, Payload, Signature).
• Вся информация о пользователе хранится внутри токена в зашифрованном/подписанном виде. Сервер не хранит состояние в БД, а проверяет криптографическую подпись своим секретным ключом.
• Главный минус: сложно отозвать токен до истечения срока его жизни (для этого приходится делать blacklist в Redis).

## 5. Аутентификация vs Авторизация
• Аутентификация (Authentication) — проверка подлинности: «Кто ты такой?» (проверка логина и пароля, биометрии).
• Авторизация (Authorization) — проверка прав доступа: «Что тебе разрешено делать?» (проверка ролей: гость, пользователь, создатель/модератор).

## 6. SSO (Single Sign-On)
• Технология единой точки входа, позволяющая пользователю авторизоваться один раз и получить доступ сразу к нескольким независимым сервисам (например, вход через Google, Яндекс или корпоративный Keycloak/OAuth2/SAML).

## 7. Двухфакторная аутентификация (2FA)
• Метод идентификации пользователя с использованием двух различных типов данных:
  1. Знание (логин и пароль).
  2. Владение (одноразовый TOTP-код из приложения Authenticator, SMS, push-уведомление или аппаратный ключ YubiKey).

## 8. RSA
• Асимметричный алгоритм шифрования с открытым ключом.
• Использует пару ключей:
  - Открытый ключ (Public key) — доступен всем, используется для шифрования данных или проверки цифровой подписи.
  - Закрытый ключ (Private key) — хранится строго на сервере, используется для расшифровки или создания цифровой подписи (например, подпись JWT токенов алгоритмом RS256).
