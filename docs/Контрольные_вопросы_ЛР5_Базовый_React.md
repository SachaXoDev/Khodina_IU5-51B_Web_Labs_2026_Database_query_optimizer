# Контрольные вопросы к лабораторной работе №5: Базовое SPA на React

---

### 1. Что такое React? Декларативный подход и Virtual DOM

- **React** — это компонентная JavaScript-библиотека с открытым исходным кодом для создания пользовательских интерфейсов (UI), разработанная компанией Meta.
- **Декларативный подход:**
  В отличие от императивного программирования (где разработчик напрямую манипулирует узлами дерева DOM через `document.createElement`, `appendChild` и т.д.), в React описывается **желаемое конечное состояние интерфейса** в зависимости от текущих входных данных (`UI = f(state)`). React берет на себя всю рутину по вычислению разницы и обновлению браузерного DOM.
- **Virtual DOM (Виртуальный DOM) и процесс согласования (Reconciliation):**
  Virtual DOM — это легковесное представление реального DOM-дерева в виде обычного JavaScript-объекта в оперативной памяти.
  1. При изменении состояния (`state`) React строит новое дерево Virtual DOM.
  2. Алгоритм диффинга (Diffing Algorithm) сравнивает старое виртуальное дерево с новым.
  3. Вычисляется минимально необходимый набор изменений (патч).
  4. Механизм React Fiber пакетно (batching) применяет только изменившиеся узлы к реальному DOM браузера, избегая дорогостоящих глобальных перерисовок (`reflow` и `repaint`).

### 2. Props (Свойства) и State (Состояние). Различия и правила передачи данных

- **Props (входные свойства):**
  - Неизменяемые (read-only, immutable) данные, передаваемые от родительского компонента дочернему (однонаправленный поток данных — *one-way data flow*).
  - Компонент не имеет права мутировать полученные `props`.
  - Используются для параметризации и конфигурирования дочернего компонента.
- **State (внутреннее состояние):**
  - Локальные, изменяемые данные компонента, которые могут эволюционировать во времени в ответ на действия пользователя, сетевые события или таймеры.
  - Управляются с помощью хука `useState`.
  - При каждом вызове функции обновления состояния (`setState`) React планирует повторный рендеринг (*re-render*) компонента.
- **Ключевое отличие:**
  `Props` приходят извне и доступны только для чтения; `State` рождается и живет внутри компонента и может обновляться его внутренней логикой. Если дочернему компоненту нужно уведомить родителя об изменении данных, родитель пробрасывает через `props` функцию обратного вызова (*callback*).

### 3. Компонент (Component) и Элемент (Element) в React

- **React Element (Элемент):**
  - Базовый, неделимый строительный блок React-приложения.
  - Это простой, неизменяемый (immutable) JavaScript-объект, описывающий DOM-узел или пользовательский компонент, его атрибуты (`props`) и дочерние элементы (`children`).
  - Создается с помощью синтаксиса JSX (`<div className="title">Привет</div>`) или вызова `React.createElement('div', { className: 'title' }, 'Привет')`.
- **React Component (Компонент):**
  - Это шаблон, функция или класс, принимающий на вход `props` и возвращающий дерево React-элементов.
  - Компоненты позволяют разбить интерфейс на независимые, переиспользуемые изолированные части.
  - Можно провести аналогию: **Компонент** — это чертеж или класс, а **Элемент** — это конкретный экземпляр или результат выполнения функции компонента.

### 4. Хуки useState и useEffect

- **`useState` (Хук состояния):**
  - Сигнатура: `const [state, setState] = useState(initialValue);`
  - Позволяет функциональным компонентам сохранять и изменять внутреннее состояние между рендерами.
  - Возвращает кортеж из двух элементов: текущего значения состояния и функции для его обновления.
  - Поддерживает функциональное обновление: `setCount(prev => prev + 1)` для избежания состояния гонки (*race condition*).
- **`useEffect` (Хук эффектов):**
  - Сигнатура: `useEffect(() => { /* effect */ return () => { /* cleanup */ }; }, [dependencies]);`
  - Предназначен для выполнения побочных эффектов (*side effects*): сетевые запросы к API, подписки на события, прямое взаимодействие с браузерным API, запуск таймеров.
  - **Массив зависимостей:**
    1. Не передан: эффект выполняется после *каждого* рендера.
    2. Пустой массив `[]`: эффект выполняется *один раз* при монтировании компонента (аналог `componentDidMount`).
    3. `[prop, state]`: эффект выполняется при монтировании и повторно при изменении любого значения из массива.
  - **Функция очистки (cleanup function):** код внутри `return () => { ... }` выполняется перед размонтированием компонента (аналог `componentWillUnmount`) или перед следующим запуском эффекта для предотвращения утечек памяти.

### 5. Жизненный цикл функционального компонента

В функциональных компонентах жизненный цикл моделируется через последовательность фаз рендеринга и хук `useEffect`:

1. **Фаза монтирования (Mounting):**
   - Выполняется тело функции компонента (инициализация `useState`, вычисление JSX).
   - React конструирует виртуальное дерево и вставляет узлы в реальный DOM.
   - Срабатывают эффекты `useEffect` с пустым массивом зависимостей `[]`.
2. **Фаза обновления (Updating):**
   - Вызывается при изменении `props` от родителя или локального `state`.
   - Компонент повторно вызывается (re-render), вычисляется новое виртуальное дерево.
   - Происходит согласование (reconciliation) и точечный патч DOM.
   - Выполняются функции очистки предыдущих эффектов, после чего запускаются новые эффекты `useEffect`, чьи зависимости изменились.
3. **Фаза размонтирования (Unmounting):**
   - Компонент удаляется из DOM (например, при смене роута или скрытии по условию).
   - Вызываются все функции очистки (`cleanup`) из `useEffect`, освобождаются ресурсы (отписка от сокетов, удаление слушателей событий).

### 6. Vite и Babel: назначение и различия

- **Babel:**
  - Транспайлер JavaScript.
  - Преобразует современный синтаксис ECMAScript (ES6+, ESNext, JSX, TypeScript) в обратно-совместимый код стандарта ES5/ES6, понятный старым версиям веб-браузеров.
  - Преобразует JSX-теги в вызовы функций `React.createElement` или `_jsx()`.
- **Vite:**
  - Инструмент сборки нового поколения и сервер разработки (*dev server*).
  - В режиме разработки Vite не выполняет предварительную сборку всего бандла в один файл (в отличие от Webpack/CRA). Вместо этого он использует нативные **ES-модули (ESM)** браузера и молниеносный компилятор **esbuild** (написанный на Go).
  - Обеспечивает мгновенный холодный старт сервера (< 300 мс) и сверхбыструю горячую замену модулей (**HMR** — Hot Module Replacement) независимо от размера приложения.
  - Для продакшен-сборки (`npm run build`) Vite использует высокоэффективный сборщик **Rollup** с продвинутой оптимизацией и разделением кода на чанки (*code splitting*).
