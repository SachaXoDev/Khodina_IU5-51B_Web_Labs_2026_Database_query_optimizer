## 1. Цель работы и соответствие заданию

Разработать базовый интерфейс SPA-приложения на React, TS для гостя, аналогичный двум страницам из лабораторной работы №1 для просмотра услуг: **лента** и **плитка**.

### Соответствие ограничениям и требованиям ТЗ:
1. **Три страницы приложения:**
   - **Плитка (Каталог)** (`/`): 2-колоночная сетка мобильных карточек услуг с фильтром по `cardinality` (числовое поле + интерактивный слайдер), бейджами лайков и кнопкой удаления карточки из локального состояния.
   - **Лента (Vibes Feed)** (`/feed`): полноэкранный видео/медиа-слой Reels/TikTok, боковая панель действий («Лайк», «Далее»), числовые метрики (`CARDINALITY`, `ВРЕМЯ`), плашки типа индекса/таблицы и сворачиваемое описание («больше / меньше»).
   - **Подробнее (Детальный экран)** (`/detail/:id`): открывается при нажатии на плитку, сохраняет визуальный стиль полноэкранного плеера с кнопкой «✕ Закрыть» для возврата к каталогу.
2. **Получение данных:** Содержимое карточек получается **только из коллекции mock-объектов** (`src/modules/mock.ts`) без бэкенда.
3. **Изображение и видео по умолчанию (в самом проекте):**
   - Статическое изображение: `frontend/public/DefaultImage.jpg` (23.8 КБ).
   - Статическое видео: `frontend/public/DefaultVideo.mp4` (66 КБ).
   - Если в услуге поле `imageUrl` или `videoUrl` отсутствует, срабатывает fallback `onError` / отображение файлов по умолчанию. На карточках каталога без изображения выводится наглядный бейдж `default image` (услуги 3 и 4).
4. **Навигационная панель (TabBar) снизу из 4 пунктов:**
   - Порядок пунктов: **Лента** (`/feed`), **Добавление** (`/create` 🔒 disabled), **Плитка** (`/`), **Вход** (`/login` 🔒 disabled).
   - Ровно **два пункта активны** (Лента и Плитка), два пункта заблокированы для гостя с атрибутом `disabled` и иконкой замка.
5. **Компоненты React-Bootstrap:** Панель фильтрации реализована на компонентах `Form`, `Form.Control`, `Form.Range` и `Button`.
6. **Никакого Redux и Context API:**
   - `Redux` не подключен (пакеты `@reduxjs/toolkit` и `react-redux` отсутствуют).
   - `React Context` не используется.
   - Состояние карточек инициализируется через `useState(MOCK_INDEXES)` в корневом `AppLayout.tsx` и прокидывается дочерним страницам через стандартный механизм `useOutletContext<AppOutletContext>()` библиотеки `react-router-dom`.

## 2. Описание страниц приложения, кнопок и полей

### 2.1. Страница «Плитка» (`ListPage.tsx`, маршрут `/`)
- **Поле ввода Cardinality (`Form.Control`):** числовое поле поиска для точного приравнивания мощности индекса (например, ввод `10000` находит индекс `idx_orders_customer_id`).
- **Кнопка «Найти» (`Button`):** отправка формы и применение фильтра к mock-коллекции.
- **Слайдер мощности (`Form.Range`):** ползунок с делениями 0, 1.5M, 3M, 5M+ для мгновенной живой фильтрации.
- **Карточка индекса (`IndexCard.tsx`):**
  - Обложка (изображение или `DefaultImage.jpg` с отметкой `default image`).
  - Бейдж количества лайков с сердечком (зелёное при `isLiked === 1`).
  - Название индекса, связка `таблица.колонка`, числовое значение `Cardinality`.
  - Кнопка логического удаления `✕` (`.tile-delete-btn`): удаляет карточку из локального состояния `cards` на клиенте.
  - Тап по карточке: переход на детальный просмотр `/detail/:id`.

### 2.2. Страница «Лента» (`FeedPage.tsx`, маршрут `/feed`)
- **Медиа-слой:** циклический плеер видео (при наличии `videoUrl`) либо заглушка `DefaultVideo.mp4`.
- **Верхняя плашка:** фирменный логотип с зелёным индикатором `DB OPTIMIZER` (без лишних счётчиков).
- **Боковая панель справа:**
  - **Кнопка «Лайк»:** инкремент/декремент счётчика лайков текущего индекса в локальном состоянии.
  - **Кнопка «Далее»:** циклический переход к следующей услуге по списку `(i + 1) % N`.
  - **Метрика «CARDINALITY»:** мощность текущего индекса.
  - **Метрика «ВРЕМЯ»:** оценочное время создания индекса (`~Xs`).
- **Нижний оверлей:**
  - Бейджи типа индекса (`B-Tree`, `BRIN`, `Hash`, `GIN`) и целевого столбца.
  - Заголовок индекса.
  - Текст описания и кнопка **«больше / меньше»**: раскрывает полное описание с плавной прокруткой или сворачивает его до 2 строк (приподняты над таб-баром на `bottom: 74px`).

### 2.3. Страница «Подробнее» (`DetailPage.tsx`, маршрут `/detail/:id`)
- Открывается по клику на плитку из каталога.
- Содержит кнопку **«✕ Закрыть»** в левом верхнем углу для возврата к каталогу (`navigate(ROUTES.LIST)`).
- Полный медиа-слой, боковые параметры и раскрывающееся описание.

### 2.4. Навигационная панель (`TabBar.tsx`)
- Закреплена внизу экрана высотой `64px`:
  1. **Лента** (`/feed`) — активная навигация.
  2. **Добавление** (`/create`) — заблокировано (`disabled`, 🔒).
  3. **Плитка** (`/`) — активная навигация.
  4. **Вход** (`/login`) — заблокировано (`disabled`, 🔒).

## 4. Расчет аппаратных требований (1 страница)
Полный математический расчет требований к серверу (RPS, ядра, ОЗУ, дисковое пространство на 5 лет с байтовой раскладкой полей) оформлен в файле:  
👉 **[docs/Расчет_аппаратных_требований_ЛР5.md](docs/Расчет_аппаратных_требований_ЛР5.md)**

*Краткие результаты расчета:*
- $RPS_{avg} = 6{,}25 \text{ запросов/с}$, $RPS_{peak} = 21{,}88 \approx 22 \text{ запросов/с}$.
- Вычислительные ресурсы: **4 vCPU** (из расчета $\lceil 22 / 50 \rceil \cdot 2 \cdot 1{,}5$) и **16 ГБ RAM** (по 4 ГБ на 1 vCPU).
- Объем строки в СУБД: $S_{row} \approx 1\,222 \text{ байт}$.
- Дисковое пространство за 5 лет с учетом индексов, WAL, медиа и запаса: **1 ТБ NVMe SSD**.

## 5. Ответы на контрольные вопросы
Развернутые ответы на все теоретические вопросы к защите ЛР-5:  
👉 **[docs/Контрольные_вопросы_ЛР5_Базовый_React.md](docs/Контрольные_вопросы_ЛР5_Базовый_React.md)**

1. **React:** компонентная архитектура, однонаправленный поток данных, декларативный подход.
2. **Props и состояние (State):** неизменяемые входные параметры vs внутренние реактивные данные компонента.
3. **Компонент и элемент:** функция/класс (шаблон/чертеж) vs легковесный виртуальный DOM-узел (`ReactElement`).
4. **useState и useEffect:** управление состоянием и работа с побочными эффектами (синхронизация, таймеры, подписки).
5. **Жизненный цикл компонента:** этапы Mounting, Updating, Unmounting и их эквиваленты в хуках (`useEffect`).
6. **Vite и Babel:** сравнение Native ES Modules + esbuild/Rollup против классической транспиляции AST через Babel + Webpack.
