# Лабораторная работа №5: Разработка базового SPA на React

## Тема проекта
**«Оптимизатор запросов баз данных (Database Query Optimizer)»** — базовое SPA-приложение на React + TypeScript (сборщик Vite), реализующее интерфейс просмотра услуг гостем по аналогии с лабораторной работой №1 в мобильном вертикальном формате (колонке 390–440px).

---

## 1. Стек технологий
- **Библиотека UI:** React 19 (функциональные компоненты + хуки)
- **Язык:** TypeScript
- **Сборщик и Dev-сервер:** Vite 8
- **Маршрутизация:** React Router v7 (`react-router-dom`)
- **Компонентная библиотека:** Bootstrap 5.3 + React Bootstrap
- **Менеджер состояний:** **Без Redux и без React Context** (согласно строгим требованиям ЛР-5 данные прокидываются через `useState` и `Outlet context` в `AppLayout.tsx`)
- **Источник данных:** Модуль `mock.ts` с объектами предметной области и возможностью подключения к API через Vite Reverse Proxy

---

## 2. Страницы приложения, кнопки и поля

### 2.1. Страница 1: «Плитка каталога услуг» (Маршрут `/`)
Витрина карточек конфигураций индексов в один столбец для удобного просмотра на мобильном экране:
* **Поля фильтрации (`FilterBar`):**
  - Текстовое поле ввода: поиск по названию индекса или таблицы (`search`).
  - Выпадающий список `<Form.Select>`: фильтрация по типу индекса (`B-Tree`, `BRIN`, `Hash`, `GIN`).
  - Числовое поле ввода: минимальная кардинальность таблицы в строках (`minCardinality`).
* **Кнопки:**
  - Кнопка **«🔍 Применить»** — выполнение фильтрации коллекции через функцию `loadData`.
  - Кнопка **«Сброс»** — сброс всех полей фильтра к исходным значениям.
* **Карточки услуг (`IndexCard`):**
  - Изображение услуги (при отсутствии подставляется дефолтное `/DefaultImage.jpg` с соответствующим бейджем).
  - Бейдж типа индекса (`B-Tree`, `BRIN` и др.).
  - Название индекса, имя таблицы, целевая колонка, краткое описание.
  - Количество строк (`cardinality`) и счетчик лайков.
  - Вся карточка кликабельна: по нажатию открывается страница «Подробнее» (`/detail/:id`).

### 2.2. Страница 2: «Лента услуг» (Маршрут `/feed`)
Вертикальный полноэкранный просмотр медиаматериалов по услугам:
* **Медиа-блок:**
  - Если у услуги есть ссылка на видеоролик (`videoUrl`), воспроизводится видео `<video autoPlay loop muted playsInline />`.
  - Если видео отсутствует, отображается обложка (`imageUrl`) либо дефолтное изображение (`/DefaultImage.jpg`).
* **Оверлей с информацией:**
  - Бейдж типа индекса и счетчик позиции (например, «1 из 4»).
  - Название индекса, целевая таблица и колонка.
  - Описание оптимизации запроса.
* **Кнопки циклической навигации:**
  - Кнопка **«⬅️ Предыдущая»** — циклический переход к предыдущей услуге `(i - 1 + N) % N`.
  - Кнопка **«Следующая ➡️»** — циклический переход к следующей услуге `(i + 1) % N`.

### 2.3. Страница 3: «Подробнее» (Маршрут `/detail/:id`)
Детальный просмотр конкретной выбранной карточки:
* **Кнопка «⬅️ К списку»** — возврат на страницу плитки.
* **Медиа-контейнер:** отображение видеодемонстрации или изображения.
* **Информационный блок:**
  - Название индекса, имя таблицы, колонка.
  - Полное описание оптимизатора и анализ EXPLAIN.
  - Кардинальность таблицы и оценочное время создания индекса.
* **Кнопка «Далее ➡️»:**
  - Переход к следующей карточке **по порядку в текущем списке** (массиве `cards`).
  - При достижении конца списка циклически открывает первую карточку.

## 3. Нижняя таб-панель навигации (`TabBar`)

Внизу мобильной колонки зафиксирована таб-панель из **4 пунктов**:
1. **«Плитка» (`▦`)** — активна, переход на `/`.
2. **«Лента» (`▶`)** — активна, переход на `/feed`.
3. **«Добавление» (`➕ 🔒`)** — **недоступна гостю (`disabled`)**, отображает замочек блокировки.
4. **«Вход» (`👤 🔒`)** — **недоступна гостю (`disabled`)**, отображает замочек блокировки.

## 4. Изображение по умолчанию (`/DefaultImage.jpg`)

В директорию `frontend/public/` помещено графическое изображение `DefaultImage.jpg` (600×400 px, dark tech-дизайн оптимизатора БД).  
* В `IndexCard.tsx` и `DetailPage.tsx` реализован fallback:
  ```tsx
  <Card.Img
    variant="top"
    src={item.imageUrl || '/DefaultImage.jpg'}
    onError={(e) => { (e.target as HTMLImageElement).src = '/DefaultImage.jpg'; }}
  />
  ```
* Если `imageUrl` пустой (как у услуг с id=3 и id=4 в mock-данных), автоматически отрисовывается дефолтная заглушка с бейджем «Изображение по умолчанию».

## 5. Порядок показа лабораторной работы преподавателю

1. **Скриншоты 1–3 (Три страницы с mock-данными):**
   * Скриншот 1: Страница «Плитка» (`/`) с карточками услуг и панелью фильтров.
   * Скриншот 2: Страница «Лента» (`/feed`) с видео/картинкой и кнопками переключения.
   * Скриншот 3: Страница «Подробнее» (`/detail/1`) с подробным описанием и кнопкой «Далее».
2. **Скриншоты 4–5 (Реализация изображения по умолчанию):**
   * Скриншот 4: Карточка в каталоге с `DefaultImage.jpg` (для карточек без своего фото, например id=3 "idx_users_email_hash").
   * Скриншот 5: Фрагмент кода тернарного оператора и `onError` в компонентах `IndexCard.tsx` и `DetailPage.tsx`.
3. **Скриншоты 6–7 (Код компонентов фильтрации и передаваемые props):**
   * Скриншот 6: Код компонента `FilterBar.tsx` (пропсы `search`, `indexType`, `minCardinality`, обработчики `onSubmit`, `onReset`).
   * Скриншот 7: Вызов `FilterBar` в `ListPage.tsx` с пробросом пропсов и стейта.
4. **Скриншоты 8–9 (Используемые хуки React):**
   * Скриншот 8: Использование `useState` для фильтров и `useEffect` для загрузки данных в `ListPage.tsx`.
   * Скриншот 9: Использование `useParams`, `useNavigate` и `useOutletContext` в `DetailPage.tsx`.

## 6. Расчет аппаратных требований

Подробный расчет оформлен формулами с конкретными данными предметной области в файле:  
**[`docs/Расчет_аппаратных_требований_ЛР5.md`](docs/Расчет_аппаратных_требований_ЛР5.md)**
* **RPS:** 6.25 средний, 22 пиковый (1 500 пользователей, 30 услуг/день, 4 HTTP-запроса на услугу).
* **Сервер:** 4 ядра vCPU, 16 ГБ RAM (по 4 ГБ на 1 ядро).
* **Спецификация БД:** поля таблицы `database_indexes` расписаны побайтово ($S_{row} \approx 1\,222$ байта).
* **Дисковое пространство за 5 лет:** 760 ГБ $\rightarrow$ **1 ТБ NVMe SSD**.
